The running order

Fifteen minutes. The italic line under each step is spoken, not read. Pick the run, then Start and Stop each step; the page keeps both timings.

   

00:00
1 min

Open

Screen already mirrored. Four tabs open in this order: register, the inbox folder in Finder, the status page, a Terminal in the delivery project. Nothing else on screen.

Every method gets described. This one I can show you, because it runs on its own. Fifteen minutes, three screens and one thing happening live.

01:00
3 min

The register

Open the register. Pick one row that is SUPPORTED and read its source aloud. Then filter to HELD and pick one. Say why it is held. Do not scroll; two rows is the demonstration.

Every factual claim from every conversation lands here with who said it, where, what it rests on and a verdict. A held claim never reaches a page the client sees. That is not a rule someone remembers; it is a build that refuses.

04:00
5 min

The intake, live

Drag the demo clip from the desktop into the inbox folder. Say the name aloud as you drop it: market, subject, room size, language. In the Terminal, start the gate now; it takes about two and a half minutes and runs while the tape does. Within about fifteen seconds the agent picks the tape up; the transcript and the ear-check page follow. While it runs, explain the two tokens on the filename and why a person supplies them. When the ear-check page appears, open it and play one turn.

The recording is the only thing a person has to make. The name carries the two facts a machine cannot know: how many voices were in the room, and what language they spoke. Everything after that is derived, which is why a fourth market inherits it on day one.

09:00
3 min

A page the client sees

Open the status page. Point at one figure and say the wording it uses. Then say which figure is missing from it and why. Do not open the register again; the point is the distance between the two surfaces.

This is what the client opens. The number on it is the wording we can defend, sourced back to the row you just saw. The one you will not find on it is held, and the page cannot print it.

12:00
2 min

The gate

The gate you started during the drop has finished. Read the GO line and one of the checks it passed. If it says NO-GO, read the reason aloud; that is the demonstration working.

One command runs every check before anything leaves. It has refused a real send. A method whose own check is always red is a checklist people ship past; this one is a check.

14:00
1 min

Close

Close the tabs. Say the one line and stop.

That is the method: recordings in, an evidence base out, and a close-out that will not let a market finish until what it taught is written down for the next one. What we would do next is run it somewhere new.

If something goes wrong

The drop does nothing for a minute

Say so. Open the fallback ear-check page from the desktop folder and continue; the pipeline is shown, not simulated. After the room: read the debug log.

The tape halts with an _ATTENTION_ note

Open the note. It carries the one command that restarts the tape. Run it in the Terminal in front of them; a halt that names its own fix is part of the method.

The gate says NO-GO

Read the reason aloud. It is the demonstration. Do not fix it in the room.

The laptop will not mirror

The desktop folder holds a shot of each surface and the gate's last output as text. Run the order from those; the live drop is the only step that is lost.

Someone asks for a number

Give the say-safe wording, or say it is held. Nothing else.
